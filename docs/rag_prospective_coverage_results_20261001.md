# 冻结第三版覆盖代理的新来源验证结果

## 结论

本轮没有通过预设机制门槛，当前优先解决评价可靠性和正常证据覆盖，再进行长序列验证。上一轮开发样本全部识别的结果，尚未获得新增来源的充分验证。

第三版代理的提示词、最低要点提取、原句校验与两次分类一致规则都保持冻结；所有代理要点先于回答生成，验证后未按结果调整提示词、删题或更改门槛。

## 本轮新增工作

1. 筛查 12 篇未参加此前隐蔽故障生成/代理修订的文献题。仍属于原授权的 40 题池，参加过早期原文自动评价与强故障试验，不能称为全新的外部测试集。
2. 实现局部原文跨度删除，保留各轮精确偏移、原句、删除片段和完整输出。fin_013 参数题成功只移除过采样前 n_estimators=100 的支持，保留其余三个参数。
3. 3 道题（fin_007、fin_013、fin_022）得到有效干预，生成 9 条全新配对回答：原上下文、语义缺失、前置文本但保留全部原证据各 3 条。
4. 其余 9 道筛查失败全部保留：6 道普通缓存未完整支持当前冻结必要事实，3 道在预设次数内未隔离目标事实。没有将失败删除或替换为其他题。

## 原因已经定位

- **5 条代理 U 来自回答摘录校验**：模型引用了 AUC 这类不足4字的实体，省略了回答中的 Markdown 加粗标记，或改写了回答中的原句。严格逐字校验保留 U，没有事后把这些结果改成成功。
- **1 条代理 U 来自临时依据范围**：要点混合了核心定义与可选扩展，最低范围核查未通过。
- **3 条质量 U 都出现评分自相矛盾**：总质量写为2，但分项同时标为 partial/missing。程序正确保留 U。
- **部分必要范围存在分歧**：fin_007 冻结事实要求多期动态观点更新，临时核心定义没有要求这一扩展；fin_022 冻结集合包括 ROC 与 AUC，而部分缓存和提取集合仅列 AUC。需独立核查最低必要范围，不能依据已有回答调整答案标准。

这些结果区分了取证不足、自动评价格式不符合要求及必要范围争议，尚不足以断言全部是回答模型或检测器自身的语义识别失败。

## MinerU 原文的本地检索诊断

额外进行了纯本地诊断，未调用 API、未修改正式 RAG 服务或本轮验证数据。读取 29 篇冻结 MinerU 原文，建立 2014 个重叠窗口；输入只有问题和原缓存实际可见来源，字符 TF-IDF 筛前20个候选，本地 BGE 4096 token 重排，取前3段。标准事实不参与检索或排序。

12 题的 40 个冻结原文摘录：原缓存逐字出现 **14/40**，新检索逐字出现 **30/40**，实际可见来源的全文中出现 **40/40**。6 题逐字命中增加，0 题减少。

**这是原文摘录可用性指标，不是语义覆盖率或回答正确率。** 同义表达可能没有相同摘录，取到原文也不保证回答完整。结果支持继续利用已有 MinerU 文本，尚无需重新解析 PDF；新检索配置还需要语义核查与新生成回答验证。

## 验证与后续

137 次 API 响应均为新的唯一 ID，累计 271266 token；请求 deepseek-chat，实际均为 deepseek-flash。9 条生成回答均正常结束。代码、输入、模型哈希、精确删除偏移、代理字段白名单、阶段顺序和所有派生分数审计通过；相关 **38 项测试通过**。本轮代码、报告和汇总同步到备份仓库，完整证据与 API 原始记录保留在项目结果目录。

下一步按以下顺序进行：

1. 开发可追踪的回答文本引用校验：区分 Markdown 展示标记与真实内容，短实体使用真实上下文跨度，无法锚定的改写仍保留 U。新版本不覆盖第三版验证结果。
2. 在不提供模型回答的条件下重新核查最低必要范围，保留争议；针对具体参数、步骤和模型名单扩充依据清楚的验证题。
3. 将完整 MinerU 检索作为后续候选配置，先验证语义支持及正常回答质量，再独立冻结覆盖代理与测试集。
4. 上述问题解决后，再冻结正常校准与长正常流、弱变化流方案，并比较简单检测基线。

当前不需要安排新的人工复核；评价 U 与必要范围争议可以继续用自动核查和保守判定处理。
