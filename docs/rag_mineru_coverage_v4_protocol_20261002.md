# MinerU 全文检索与覆盖代理 V4 开发协议

## 固定范围

使用原40题池中的12道已用题：fin_007、008、011、013、014、017、019、022、023、024、036、039。每题对照原缓存与按问题检索的完整MinerU来源证据。另使用前一版本已经验证的fin_013缺少过采样前n_estimators=100的证据作为固定对照。

共25条新生成答案；题目和证据条件不按新回答质量筛选。结果应标明开发验证，不能称为独立来源泛化测试。API数据属于用户已明确授权的原40题及相应内容。

## 固定顺序

1. 锁定代码、输入、29篇MinerU文本哈希和检索配置。
2. 仅查看问题与原始论文片段，重建最低必答集合，两轮审查。两轮集合不一致或摘录无效均保留U。
3. 仅查看问题与全文检索证据，建立临时代理事实。代理输入没有旧标准答案、规范事实、题号或实验条件。
4. 在新答案生成前核查两组证据的语义支持，锁定全部依据、证据审查与25条公开输入。
5. 固定模型别名deepseek-chat、temperature=0、max_tokens=512，与原实验系统提示一致。保留实际返回模型名称、响应、usage、结束原因。
6. 离线依据和临时检索代理分别两轮逐点判断。V4仅处理展示标记、真实短实体的引用位置；最多一次引用复制修正，语义判定不变。不确定、分歧和格式错误保留U。
7. 从原始API响应重算逐点质量和检测信号，核对输入白名单、生成前冻结、原始片段位置和唯一新响应ID。

## 检索与门槛

检索沿用本地诊断固定配置：2000字符窗口，1500字符步长，字符TF-IDF 2–3 gram，前20个候选，本地BGE最多4096 token重排，前3段。范围由原缓存实际可见论文元数据确定，规范事实不参与检索。

预设开发门槛：至少10/12题依据有效；有效依据题的全文检索语义完整率至少80%；代理U不超过20%；确定完整回答误报为0；至少5条确定不完整回答，检出率至少80%且U计未检出；固定缺参数对照应判不完整并检出。门槛未通过时报告失败原因，后续修改另立版本。
