# 无人工复核的自动评价方案（2026-10-01）

## 采用的研究口径

原审阅者无法继续复核，实验改用自动评价与原文证据核验。两份原始人工表及导入审计保留，作为标注质量诊断；不修补、猜测或冒充人工标签，也不把自动复评分数写入人工 final_* 列。

不再等待人工复核即可推进离线机制实验和变点方法实验。论文或报告注明“自动评价；尚无可靠人工验证”，结论范围与实际评价来源一致。

本文件是后续实施方案；本轮未执行新的 API 评分、PDF 全量核查或在线实验。

## 现有基础与需修正的问题

- 已有 40 道正式题、80 条固定答案、29 篇来源文献、证据移除审计、基线复测和少量匹配 placebo 结果。
- `evaluate.py::llm_judge` 已可自动打正确性和忠实性分，但生成器与评审均使用同一 DeepSeek 模型。
- 现有结果中有两条明确拒答却被评为正确性高分；后续必须把“是否答出了问题”和“拒答是否符合所给证据”分开。
- 显式拒答代理可以作为在线可观测信号，其测量的是拒答行为，不能直接代表回答正确率。
- 固定题集经过既有质量和检索命中筛选；自动评价方式改变后仍是条件性机制实验。

## 第一步：题目级证据核验

按 40 道问题处理，不对 80 条模型回答各自改写标准答案。

1. 根据原标注文献定位 PDF 及相关页码，本地提取相关文本；核查问题是否明确、旧标准答案是否被原文支持及足以回答问题。
2. 这一阶段只使用问题、原标准答案和原论文，不向核验器展示正常／故障回答、实验条件、旧评分或人工标签。
3. 提取必要答案事实点，保存来源文件、PDF 页号（注明阅读器页号或印刷页号）、原文摘录、原文文本哈希及判定理由。程序核对摘录确实出现在对应提取文本；摘录存在本身不保证语义支持成立。
4. 输出“证据支持”“有冲突”“未定”。未定保留，原题库保持冻结；需要修订的标准答案形成独立版本及修改记录。
5. 同一道题的两个条件共用同一证据核验结果和答案事实点，避免按哪个条件回答好来选题。

这里是自动核验，不称为人工金标准。PDF 提取、页码定位或语义关系不可靠时不强行判定。

## 第二步：答案评价与行为评价分开

对固定 80 条答案重评，不重新生成答案。使用随机盲 ID，评审输入中去掉条件、qid、旧评分和人工标签。

| 维度 | 输入与评价目标 | 特别约束 |
|---|---|---|
| 是否明确拒答 | 问题与模型回答；规则与模型判断分别记录 | 回答错误不等于拒答；解释概念时的一般“无法判断”不等于拒答 |
| 是否答出问题 | 问题、经原文核验的必要事实点、模型回答 | 两条件使用相同核验材料；未回答记未答出，不能因拒答合理给高正确性 |
| 回答有无证据支持 | 模型回答与生成时实际可见上下文 | 使用当时提示可见内容，不用未展示给生成器的缓存片段代替 |
| 参考答案是否充分 | 第一阶段题目级结果 | 不随模型回答改变 |

按照事实点给出覆盖、错误和未定判断，保留支持的摘录及理由。可借鉴 RAGChecker 的 claim-level 检查思路；不把词面 F1 或单个主观总分作为唯一正确性依据。

先用虚构的“正确作答”“错误直接作答”“明确拒答”“一般无法判断措辞”检查评审是否遵守字段定义，再以固定提示重评全部答案。调整规则的过程单独记录；不能看条件差异后调整评分阈值。

## 第三步：稳定性与不确定性

- 现有 DeepSeek 接入可用于自动评审；同一模型的两轮评分只能作为重复测量，不能称为两名独立评审。
- 若后续已有其他模型的可用接入，可用不同模型家族做交叉复评；不把多模型一致误称为已证明正确。
- 记录模型标识、提示版本、采样参数、时间、响应、解析状态和输入哈希，评审错误不记为模型答错。
- 对规则和模型判断冲突、重复评价不稳定、引用不匹配的回答保留未定；不得按期待的实验方向补值。
- 同时报告确定项目的结果、未定比例，以及把未定分别视为成功／失败时的上下界或配对最坏情形。若结论对未定处理敏感，只报告评价不确定性。

## 第四步：配对效果与变点验证

1. 对已经核验的题目，以题目为配对单位，报告答案事实点覆盖、明确拒答及成功代理的正常／故障差异。成功代理要求答出问题且未拒答；如果输出未定，保留未定。
2. 标准答案不足的题不强行加入正确性主统计，但其拒答行为可以独立报告；所有排除项和两条件分母明确列出。文献共享导致的依赖要反映在区间估计中。
3. 现有自动结果可以作为初步参考，标为旧评分代理，不改称人工验证结果。
4. 检测器采用部署时真正可获取的观测量，例如显式拒答代理。原论文、标准答案和离线正确性标签只用于离线验证，不作为无标签在线检测时的输入。
5. 用独立正常请求序列校准和检验误报，用预设故障序列研究检测延迟；固定 40 题重排只能用于演示。阈值校准序列与最终测试序列分开。

## 工作分工

无需用户再招募人工复核者。代码、原文证据整理、自动评审及统计可以由助手完成；缺少原始论文、外部模型接入或遇到重复授权以外的数据传输需求时，再说明具体缺口。当前不用新增外部模型或扩大题库，也不直接安装新的 RAG 框架。

## 方法来源

- [Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena](https://arxiv.org/abs/2306.05685)：研究自动评审的适用性及位置、冗长、自偏好等偏差；不能据此把本项目未校验的自动评审当成人工结果。
- [RAGChecker](https://arxiv.org/abs/2408.08067) 与 [官方实现](https://github.com/amazon-science/RAGChecker)：按事实声明核验检索和生成的思路。本方案参考其评价划分，不声称已经复现该框架或拥有其论文中的人工相关性结果。
