# 冻结第三版覆盖代理：新生成回答与新增来源验证

## 本轮范围

候选方法固定为上一轮第三版：补充检索最低必要事实及原文摘录，回答中的真实原句核查，两次分类一致才给确定结果。提取、最低范围、回答核查提示词与判断函数保持原方法，哈希在开始前锁定。验证后不按结果修订候选方法。

预设筛查 12 道题：fin_007、008、011、013、014、017、019、022、023、024、036、039。这 12 篇文献不与之前 11 篇隐蔽故障生成/代理开发文献重叠。它们来自原始授权的 40 题池，参加过更早的原文自动评价及强故障试验，不是完全未使用过的外部测试集；其中 013、023、024 在上一轮筛查失败，未生成代理开发回答。

## 干预与筛查

1. 两次核查原上下文是否完整支持冻结的必要事实。仅当 supported 摘录不逐字匹配导致 U 时，允许一次严格原文复制的重试；原记录保留，真实语义 U 不自动重试。
2. 每题预设最多 2 个目标、每个目标最多 2 轮删除。一般优先最后一个事实、其次第一个；fin_013 优先第一个参数，其次第二个。全部在生成前确定。
3. 映射目标的全部同义/间接/重复支持，按原文中的最小子句、参数键值或局部片段删除，片段必须在指定句段中真实出现。记录各轮原文偏移和删除内容，保护来源标题。不改写原文，不补造事实。
4. 两次核查均确认目标 absent 且其他必要事实 supported 才合格。所有筛查失败保留。按上述题号顺序最多选择 8 道合格题，选择与新生成回答质量无关。
5. 每题 3 个条件：原上下文、语义缺失、前置无关文本但保留全部原证据。局部删除是人工构造故障，尚不代表真实在线故障分布。

## 冻结与执行

先锁筛查输入，再锁合格案例/私有事实与条件键，再从问题和实际可见来源检索证据并锁定代理要点，之后才生成新回答。检索证据库沿用 40 个原正常缓存上下文；代理计划与请求不读取冻结标准答案/事实清单。干预构造和离线质量评价允许使用原文冻结事实。

请求模型 deepseek-chat，temperature=0，max_tokens=512，沿用生成提示词；记录实际模型标识、响应 ID、token 和结束状态。所有回答新生成，无旧回答复用。质量用两次事实评分，quality=2 定义完整，与拒答规则解耦。另核查回答对当前可见上下文的支持。

## 预设机制门槛

进入下一轮长序列设计的门槛同时要求：

- 至少 5 道合格配对题、至少 10 条质量 2 的完整回答。
- 至少 5 个语义缺失配对出现质量下降，其中至少 3 个没有规则拒答。
- 完整回答上的代理误报为 0；代理 U 占全部答案不超过 20%。
- 全部已知不完整回答中至少 80% 被代理标为不完整，U 计为未检出。
- 所有已知质量下降且没有规则拒答的语义缺失回答都被代理标为不完整。

这些是预设小样本机制门槛，不是总体置信界、总体错误率或长期误报控制。未通过时保留结果，下一阶段优先分析失败机制，不通过改提示词、换题或调整阈值让本轮通过。

报告全部筛查、每个配对、完整/不完整/U、代理可用率、检出/漏报/误报及实际调用记录。检查代码/输入/模型哈希、阶段锁、代理白名单、响应 ID 唯一与所有案例保留。

若机制门槛通过，再制定并冻结长正常流与弱变化流的校准和预算。长序列仍需新 API 调用、独立正常校准和简单检测基线比较；本轮不以答案级结果代替变点序列结果。DeepSeek 同时生成和评价，两次自动核查不是独立人工审阅。
